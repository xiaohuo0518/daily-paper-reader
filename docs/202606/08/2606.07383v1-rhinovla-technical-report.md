## 摘要
视觉-语言-动作（VLA）模型在机器人操作中显示出巨大潜力，但在边缘硬件上的实时部署仍然具有挑战性。在这项工作中，我们识别出VLM的视觉和上下文令牌是部署延迟的主要来源：对于以GEMM为主的投影算子，当模型维度固定时，计算量随输入令牌数量线性增长。基于这一观察，我们提出了RhinoVLA，这是一个面向部署的VLA模型，与慧析R1边缘SoC协同设计。RhinoVLA采用令牌高效的Qwen3-VL骨干网络和连续动作专家，减少了VLM侧的令牌和计算负担，同时保留了预训练的多模态能力。为了支持跨机器人学习，RhinoVLA进一步引入了统一接口，结合了视图注册表、72维物理状态-动作槽空间和机器人实例LoRA，使得异构机器人观测和动作模式能够在共享策略下对齐。在部署方面，RhinoVLA通过硬件感知编译、混合精度执行和并行视觉编码进行了优化。实验表明，RhinoVLA在相似参数规模下实现了与π0.5相当的下游性能，同时在慧析R1上达到了11.69 Hz的端到端推理，满足10 Hz实时闭环控制目标。项目将在https://github.com/HuixiAI/RhinoVLA开源。

## Abstract
Vision-Language-Action (VLA) models have shown strong potential for robotic manipulation, but real-time deployment on edge hardware remains challenging. In this work, we identify VLM visual and context tokens as a major source of deployment latency: for GEMM-dominated projection operators, computation grows linearly with the number of input tokens when model dimensions are fixed. Motivated by this observation, we propose RhinoVLA, a deployment-oriented VLA model co-designed with the Huixi R1 edge SoC. RhinoVLA adopts a token-efficient Qwen3-VL backbone and a continuous Action Expert, reducing the VLM-side token and computation burden while preserving pretrained multimodal capability. To support cross-robot learning, RhinoVLA further introduces a unified interface that combines View Registry, 72D physical state-action slot space, and robotinstance LoRA, allowing heterogeneous robot observations and action schemas to be aligned under a shared policy. On the deployment side, RhinoVLA is optimized through hardware-aware compilation, mixed-precision execution, and parallel visual encoding. Experiments show that RhinoVLA achieves downstream performance comparable to π0.5 at a similar parameter scale, while reaching 11.69 Hz end-to-end inference on Huixi R1, meeting the 10 Hz real-time closedloop control target. The project will be open-sourced at https://github.com/HuixiAI/RhinoVLA.

## 1. 核心问题与整体含义（研究动机和背景）

**核心问题**：视觉-语言-动作（VLA）模型在机器人操控中表现出色，但在边缘硬件（如Jetson Orin、慧析R1等SoC）上难以满足实时闭环控制（通常要求10 Hz以上）的推理速度。延迟瓶颈主要来自视觉和上下文令牌数量过多导致的GEMM计算量线性增长。

**研究背景**：
- 现有VLA模型（如π0.5、GR00T N1、RDT）使用预训练VLM骨干，参数量大，视觉令牌多（如PaliGemma每张图256个令牌），导致推理延迟高。
- 对π0.5在Orin上的分解分析显示，VLM骨干和Action Expert占总延迟的90%以上，其中MLP投影占VLM延迟的74.7%。
- 当前边缘平台（Orin）计算能力有限，难以支持10 Hz以上的VLA推理；高端平台（Thor）成本高。因此，需要算法-硬件协同设计来降低令牌开销并提升硬件利用率。

**整体含义**：RhinoVLA旨在通过**令牌高效骨干**、**统一跨机器人接口**和**硬件感知优化**，在性能与实时性之间取得平衡，实现边缘实时VLA部署，并支持异构机器人平台。

## 2. 方法论：核心思想、关键技术细节、公式/算法流程

### 2.1 核心思想
- **令牌减少**：采用Qwen3-VL骨干，只需64个合并视觉令牌/图（比PaliGemma减少4倍），直接降低GEMM计算量。
- **统一接口设计**：解决跨机器人数据集异构性问题（不同相机布局、动作维度、物理语义）。
- **硬件-算法协同优化**：针对慧析R1的架构特点进行编译、混合精度和并行编码优化。

### 2.2 关键技术细节

#### (1) 架构
- **VLM骨干**：Qwen3-VL-2B（2.13B参数），冻结主干，仅训练VLM LoRA。
- **Action Expert**：0.40B参数，基于Qwen兼容的Transformer（18层，1024隐藏维度），以最后18层Qwen3-VL的KV缓存、72维状态/动作掩码、噪声动作块、流匹配时间、机器人实例索引为输入，预测流速度。

#### (2) 统一接口三个组件

| 组件 | 解决挑战 | 技术细节 |
|------|----------|----------|
| **视图注册表（View Registry）** | 不同机器人相机布局、视角顺序和模态不统一 | 每个图像添加显式标签，如 `[head\|rgb]`、`[left_wrist\|depth]`，使模型明确相机身份 |
| **72维物理槽空间（Unified 72D slot space）** | 不同机器人动作向量长度、物理含义不同 | 固定72维语义槽（如D0-D6为臂关节弧度，D14-D15为夹爪开合比，D58-D60为基座速度等），每个机器人通过二进制掩码标记有效槽位 |
| **机器人实例LoRA** | 同一类型机器人可能存在校准、控制器、机械差异 | 在Action Expert的FFN中插入LoRA模块（每个实例一个），训练时按实例ID路由，推理时可合并到基础权重中 |

#### (3) 训练策略
- **预训练**：冻结Qwen3-VL骨干，联合优化VLM LoRA、共享Action Expert、机器人实例LoRA。使用**掩码流匹配损失**，仅对有效动作槽位计算损失，并加入残差正则化防止实例LoRA过度接管。
- **后训练（迁移）**：冻结VLM LoRA和大部分Action Expert参数，仅更新目标机器人的实例LoRA，使用少量真实机器人任务数据微调。

#### (4) 部署优化（针对慧析R1）
- **编译优化**：算子级（FlashAttention式分块、SPM内存管理）、图级（算子融合）、运行时级（细粒度任务调度）。
- **混合精度**：INT8权重 + FP16激活（W8A16），定制GEMM内核避免反量化开销，相比FP16有1.69倍加速。
- **并行视觉编码**：将三个摄像头图像批量编码，延迟从34.52ms降至24.31ms。

**最终**：在慧析R1上端到端推理达到11.69 Hz。

## 6. 主要结论与发现

1. **令牌数量是VLA部署的关键瓶颈**：通过对π0.5的延迟分解，确认MLP投影（GEMM）占总延迟75%，且计算量线性依赖令牌数。
2. **Qwen3-VL是多快好省的骨干**：在相同图像尺寸下，Qwen3-VL仅用64个合并视觉令牌，是PaliGemma的1/4，同时保留强多模态能力。
3. **统一接口有效支持跨机器人学习**：视图注册表、72维槽空间、实例LoRA三个组件协同，使共享策略能够处理异构相机、动作知识和残差适应。
4. **硬件-算法协同设计实现实时部署**：通过编译、W8A16、并行编码，在慧析R1上达到11.69 Hz，满足10 Hz实时控制要求。
5. **下游性能接近π0.5**：在LIBERO上平均90.0%，低于π0.5（96.9%），但优于其他开放VLA模型；真实机器人任务中部分超越π0.5。

## 7. 优点：方法与实验亮点

- **问题洞察精准**：从算子级分析定位令牌数量这个关键来源，而非笼统地归咎于模型大小。
