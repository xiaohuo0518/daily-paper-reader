## 摘要
目前，具身AI模型涵盖视觉-语言-动作（VLA）模型和世界-动作模型（WAM），但在实际部署中，由于模型特定的Python技术栈、后端假设以及机器人侧的胶水代码，尤其是在异构边缘设备上，部署仍然是碎片化的。现有的推理运行时主要设计用于请求-响应服务，因此无法满足具身部署的运行时要求：闭环控制中的多速率执行、异构硬件上的延迟优先批大小为1的推理，以及超越固定令牌I/O的可扩展具身接口。我们提出了Embodied.cpp，一个用于具身模型的可移植C++推理运行时。基于对代表性VLA模型和WAM的架构分析，Embodied.cpp捕获了一个共享的执行路径，并将其组织为五个层次：输入适配器、序列构建器、主干执行、头部插件和部署适配器。该运行时提供模块化的多速率执行、延迟优先的融合推理以及可扩展的运算符和I/O支持，通过一个后端抽象实现跨异构设备、机器人和模拟器的部署。我们在两个VLA模型（HY-VLA和pi0.5）以及一个使用LingBot-VA Transformer块的初步WAM基准上评估了Embodied.cpp。VLA部署实现了成功的闭环执行，任务成功率分别为100.0%和91.0%。WAM基准将块内存从312.2 MiB降低到88.1 MiB。这些结果表明，Embodied.cpp在提升部署效率的同时，在不同具身模型架构上保持了高精度。

## Abstract
Embodied AI models now span vision-language-action (VLA) models and world-action models (WAMs), but practical deployment remains fragmented across model-specific Python stacks, backend assumptions, and robot-side glue code, especially on heterogeneous edge devices. Existing inference runtimes are designed mainly for request-response serving and therefore do not satisfy the runtime contract of embodied deployment: multi-rate execution inside closed-loop control, latency-first batch-1 inference on heterogeneous hardware, and extensible embodied interfaces beyond fixed token I/O. We present Embodied$.$cpp, a portable C++ inference runtime for embodied models. Based on an architectural analysis of representative VLA models and WAMs, Embodied$.$cpp captures a shared execution path and organizes it into five layers: input adapters, sequence builders, backbone execution, head plugins, and deployment adapters. The runtime provides modular multi-rate execution, latency-first fused inference, and extensible operator and I/O support, enabling deployment across heterogeneous devices, robots, and simulators through one backend abstraction. We evaluate Embodied$.$cpp on two VLA models, HY-VLA and pi0.5, and on a preliminary WAM benchmark using a LingBot-VA Transformer block. The VLA deployments achieve successful closed-loop execution with 100.0% and 91.0% task success rates, respectively. The WAM benchmark reduces block memory from 312.2 MiB to 88.1 MiB. These results show that Embodied$.$cpp improves deployment efficiency while preserving high accuracy across diverse embodied model architectures.

- **研究动机**：当前具身AI模型（如VLA模型和WAM）在异构边缘设备（Jetson、RK板、x86边缘盒等）上的实际部署仍然碎片化，需要为每个新模型家族重写Python推理栈、后端依赖和机器人侧胶水代码。现有的通用AI推理运行时（如llama.cpp、ONNX Runtime、SGLang等）主要面向请求-响应服务场景，采用相对统一的令牌接口和吞吐量优化，无法满足具身部署的独特运行时契约：
  - **多速率执行**：感知编码器、Transformer主干、预测分支、动作执行头等需要在同一控制回路中以不同频率运行（如层次VLA、异步VLA）。
  - **延迟优先闭环控制**：优化目标不是吞吐量，而是低延迟、低抖动、高效批量-1推理，适用于异构边缘硬件。
  - **可扩展的具身接口**：需要吸收自定义算子、多模态输入（图像、语言、本体感、力触觉等）和异质输出（动作令牌、连续动作向量、动作块、世界预测等）。
- **整体含义**：需要一个统一的、可移植的C++推理运行时，既能覆盖不断增多的具身模型架构，又能直接桥接到机器人和模拟器，降低部署集成负担。

## 二、论文提出的方法论：核心思想、关键技术细节

### 1. 核心思想
- 通过对代表性VLA模型（AR-Token、VLM背骨、层次、异步）和WAM（预测-行动、统一AR建模、共享背骨、潜在空间）的体系结构分析，发现它们共享一条执行路径，主要差异集中在少数可插拔的头部和预测模块。
- 设计Embodied.cpp，将共享路径映射为**五层架构**，并基于三个设计原则：模块化多速率执行、延迟优先融合推理、可扩展操作符和I/O支持。

### 2. 关键技术细节
- **五层架构**：
  - **输入适配器 (Input Adapters)**：吸收在线传感器流和离线数据集样本（摄像头、力/触觉、IMU、基准数据集），转换为类型化的具身接口。
  - **序列构建器 (Sequence Builders)**：将多模态输入组装成模型所需的序列格式（如视觉令牌、语言令牌、状态令牌等）。
  - **主干执行 (Backbone Execution)**：执行Transformer主干或统一背骨网络，支持不同批大小和前向模式。
  - **头插件 (Head Plugins)**：可插拔的预测/动作头（如动作块解码、未来预测解码、扩散头等），允许不同模型家族定制。
  - **部署适配器 (Deployment Adapters)**：将运行时输出桥接到模拟器（ManiSkill、LIBERO、Isaac Sim）或真实机器人软件栈。
- **三个配套子系统**：
  - **模块化多速率执行**：显式暴露执行单元、可插拔模块、共享状态池和可配置刷新策略，允许不同组件以不同速率运行。
  - **延迟优先融合执行**：图回放、缓冲区重用、算子融合、后端特定调度、主机-设备数据移动优化，确保小批量推理在异构设备上高效稳定。
  - **具身AI内核仓库**：收集可重用算子和模型特定内核，随新架构演进扩展。
- **后端抽象**：通过统一后端接口支持CPU、GPU、NPU等异构硬件，无需为每个硬件重写推理路径。
