## 摘要
在移动机器人上部署数十亿参数的视觉-语言-动作（VLA）策略会引发系统冲突：语义推理受益于云GPU，而闭环控制必须在网络延迟和抖动的情况下本地响应。现有的分层和异步策略提高了吞吐量，但其慢路径表征仍可能过时到达，或需要显式调度和延迟提示。我们提出CloudEdgeVLA，一种将时间错位视为表征学习问题的云边策略。云VLA将延迟的观测编码为缓慢变化的任务特征，而轻量级边缘头则将最新可用的云特征与当前本地视觉相结合。在训练期间，当前帧和随机延迟帧在新鲜路径和过期路径中与相同的当前动作目标配对。该目标鼓励云表征保留任务级信息，同时边缘路径提供状态敏感校正。在四个LIBERO套件中，CloudEdgeVLA在40步均匀延迟窗口内保持63.8%–78.0%的成功率，而VLASH最高达到6.4%，所评估的单路径基线最高达到3.0%。通过从控制回路中移除阻塞同步，该设计为可扩展的VLA部署提供了一条实用途径，其中云模型可以不断增长，而边缘计算保持轻量级和响应迅速。

## Abstract
Deploying billion-parameter Vision-Language-Action (VLA) policies on mobile robots creates a systems conflict: semantic reasoning benefits from cloud GPUs, whereas closed-loop control must respond locally despite network delay and jitter. Existing hierarchical and asynchronous policies improve throughput, but their slow-path representations can still arrive stale or require explicit scheduling and delay cues. We introduce CloudEdgeVLA, a cloud-edge policy that treats temporal misalignment as a representation-learning problem. A cloud VLA encodes delayed observations into slowly varying task features, while a lightweight edge head combines the latest available cloud feature with current local vision. During training, current and randomly delayed frames are paired with the same current action target in fresh and stale paths. This objective encourages the cloud representation to preserve task-level information while the edge path supplies state-sensitive corrections. Across four LIBERO suites, CloudEdgeVLA retains 63.8--78.0% success with a 40-step uniform-delay window, whereas VLASH reaches at most 6.4% and the evaluated single-path baselines at most 3.0%. By removing blocking synchronization from the control loop, the design offers a practical route to scalable VLA deployment in which cloud models can grow while edge computation remains lightweight and responsive.

- **问题本质：** 在移动机器人上部署数十亿参数的 VLA（Vision-Language-Action）模型面临一个系统层面的矛盾：
  - 语义推理（如任务理解、目标规划）希望借助云端 GPU 的大算力；
  - 闭环控制（如实时动作输出）必须在本地快速响应，不能等待网络往返。
- **网络不确定性：** 云-边通信存在延迟、抖动和丢包，导致云端返回的特征描述的是过去时刻的场景，而非机器人当前所处状态；若阻塞等待新特征，控制频率降低；若直接使用旧特征，则产生时间错配。
- **现有方法的不足：**
  - 分层/异步策略（如 MResT、DP-VLA、HiRT、SmolVLA 等）提高了吞吐量，但仍需要显式调度、固定频率比或延迟提示；
  - 慢路径表征仍可能过时到达，鲁棒性在严重延迟下迅速崩溃。
- **核心转变：** 本文将延迟容忍问题**从推理调度问题重新定义为表征学习问题**，目标是通过训练让云端特征对观测年龄不敏感（保留任务级信息），同时由边缘实时视觉补充状态敏感信息，从而在非阻塞、无需时钟对齐的条件下实现鲁棒控制。

## 2. 方法论：核心思想、关键技术细节与流程

### 2.1 系统架构（CloudEdgeVLA）

系统由三个组件构成，遵循 System 1/System 2 类比（Kahneman）：

| 组件 | 角色 | 功能 |
|------|------|------|
| **云端 VLA 主干 fθ** | System 2（延迟不敏感） | 处理延迟观测与语言指令，生成高层规划表征 h = fθ(o, ℓ) ∈ R^(L×D)；使用 LoRA 适配的预训练 VLM，仅运行在云端 |
| **边缘视觉编码器 vψ** | System 1 感知（延迟敏感） | 轻量级视觉编码器（默认 SigLIP-Base），实时提取当前观测特征 z_t = vψ(o_t)，冻结不训练 |
| **边缘动作头 gϕ** | System 1 控制（延迟敏感） | 融合（可能过时的）云特征与实时边缘视觉特征，输出动作 chunk：â_t = gϕ(h_{t-k}, z_t)；结构为均值池化 + 投影 + 拼接 + 残差 MLP |

### 2.2 核心机制：配对帧双路径训练（Paired-Frame Dual-Path Training）

**关键思想：** 让动作头同时学会从新鲜和过时的云特征中产生正确动作。

- **配对帧构建：** 每个训练样本取同一 episode 中连续的 W 帧窗口，构造：
  - 当前帧 o_t；
  - 延迟帧 o_{t-d}，其中 d ~ Uniform(1, W−1)。
- **双前向传播：**
  - h_fresh = fθ(o_t, ℓ)，h_stale = fθ(o_{t-d}, ℓ)；
  - 两者均保留梯度（不 detached）。
- **相同的边缘视觉特征：** 两条路径均与同一个实时视觉特征 z_t 融合。
- **双路径损失：**
  - **L = (1−λ)·L_fresh + λ·L_stale**
  - L_fresh = ‖â_fresh − a_t‖₁，L_stale = ‖â_stale − a_t‖₁；
  - λ 采用**课程学习**策略，在前 n_warmup 步中从 0 逐渐增大至 λ_max，让主干先学习强表征再被"逼迫"变得延迟不敏感。

### 2.3 协作式部署协议（非阻塞）

1. 边缘捕获当前观测 o_t；
2. 异步发送至云端（不阻塞）；
3. 云端返回特征后，边缘更新 h_received；
4. 边缘本地实时计算 z_t；
5. 动作头输出 â_t = gϕ(h_received, z_t)；
6. 执行动作，从不等待云端特定更新。

### 2.4 涌现表征特化（Emergent Representational Specialization）

- 优化目标（stale 路径梯度）：∇θ L_stale = ∇θ ‖gϕ(fθ(o_{t-d}, ℓ), vψ(o_t)) − a_t‖₁；
- 直觉：随机延迟 d 下，仅与瞬时状态绑定的特征对预测 a_t 不可靠，而任务身份、目标和粗略进度更稳定；该目标**鼓励但不数学保证**对时间位移的不变性；
- 边缘特征 z_t 负责编码状态敏感信息，实现双向互补。

## 6. 主要结论与发现

1. **主结果：** 在 d_max=40 均匀延迟下，CloudEdgeVLA 在四个 LIBERO 套件上保持 63.8%–78.0% 成功率；VLASH 最多 6.4%，单路径基线最多 3.0%。
2. **延迟保留：** CloudEdgeVLA 的归一化延迟 AUC 为 90.8%（VLASH 仅 32.4%）；在 d_max=40 保留 76.5% 的同步成功率（VLASH 仅 1.8%）。
3. **套件差异：** Long 套件退化最大（−27.9 pp），Goal 最稳定（−18.5 pp），但仍远超最强基线 63.3 pp。
4. **消融结论：**
   - 当前边缘视觉是关键：加入 SigLIP-Base 将成功率从 31.6% 提升至 95.1%（+63.5 pp）；
   - 编码器规模不是瓶颈：SigLIP-SO400M 仅比 Base 高 0.7 pp，支持轻量部署；
   - 延迟暴露训练贡献大：stale-only 达到 89.2%，远高于 fresh-only 的 54.8%；联合训练最高（95.1%）。
5. **机制发现（离线诊断）：**
   - 在 d=20 时，主干漂移 D_h 降低 59.2%（0.391→0.160）；
   - 过时转移增益 κ 降低 72.7%（1.082→0.295）；
   - 动作漂移降低 88.9%，演示 MAE 降低 88.5%。
6. **重要的负结果（反事实审计）：** 当前边缘视觉对过时云特征的**直接修复作用极小**（edge-rescue fraction 仅 0.03%，校正向量与所需恢复方向余弦对齐仅 0.030）；该 checkpoint 的主要增益来自**更稳定的主干 + 衰减残余漂移的动作头**，而非边缘视觉的直接补偿。
7. **真实机器人（描述性证据）：** 在 1000ms 附加 RTT 下，CE-VLA 保持 80/70%（静态/动态）成功率，而 VLASH 降至 0/0%。

## 7. 优点

- **问题定义的新颖性：** 将延迟容忍从调度问题转化为表征学习问题，改变了云-边接口的语义——传输"任务特征"而非"动作计划"。
- **架构简洁且非阻塞：** 边缘始终消费最新可用云特征，无需时钟对齐、无需频率比、无需显式延迟元数据，工程部署友好。
- **训练策略精巧：** 配对帧 + 课程式 λ 调度，在不需要额外不变性损失的情况下引导涌现表征特化。
- **机制验证深入：** 不仅报告端到端成功率，还分解了主干漂移、动作头转移增益和边缘直接修复程度，并诚实报告了不利于自身假设的负结果，学术严谨性突出。
- **消融干净：** 逐项剥离编码器、损失路径，清晰归因各组件贡献。
- **部署实用导向：** 验证轻量编码器可行性，强调云模型可独立扩展、边缘保持轻量与响应。

## 8. 不足与局限

- **实验覆盖有限：**
  - 仅在 LIBERO 单一模拟器上评估，缺乏真实世界大规模验证或跨平台泛化；
  - 延迟分布仅覆盖均匀分布，未测试真实网络 trace、突发延迟、丢包或断连场景；
- **计算成本未报告：**
  - 未说明训练所用的 GPU 数量、时长、能耗；
  - 配对帧双路径训练需要**两次主干前向**（fresh + stale），训练成本高于单路径；
- **边缘能力的边界：**
  - 边缘依赖**冻结的 RGB 视觉编码器**，无法捕捉深度、力/触觉信息；
  - 反事实审计表明边缘视觉对过时云特征的直接修正能力很弱，机制主要靠主干稳定性——这限制了该方法在更极端延迟下的表现上限；
- **真实机器人证据薄弱：**
  - 10 trials/单元，作者承认仅为可行性检查，非统计功效支撑的硬件基准；
  - 边缘设备是工作站级（RTX 5080），未验证嵌入式/低功耗设备上的效率；
- **理论保证缺失：**
  - "涌现表征特化"仅是启发式目标，作者承认"鼓励但不对时间位移不变性提供数学保证"；
  - 对训练窗口（W=21）之外的延迟（d_max>20）虽有实验但仍无法保证任意延迟下的安全；
- **应用限制：**
  - 长时间断连会使任务级上下文失效，仍需时间戳特征与本地回退策略配合；
  - 静态/动态真实场景差异较大，动态条件下鲁棒性有待更多验证。
